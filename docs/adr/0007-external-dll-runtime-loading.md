# 外部系统 DLL 运行时动态加载

对外部系统 DLL（wofutil.dll、rstrtmgr.dll、ntdll.dll，及未来引入的任何系统组件含 COM）一律采用运行时动态加载（LoadLibraryW/GetProcAddress/COM 运行时激活），不做链接期导入表依赖、不引入延迟加载（delayload）——根因：MinGW 工具链无 wofutil/rstrtmgr import lib（0001 记载），运行时加载是唯一可用形态，统一为政策而非逐点权宜。加载机制统一收敛到共享 dynload 模块：每 DLL 一个聚合 struct（函数指针成员）+ 名字表 + 泛型填充函数，进程级 std::call_once 单次加载，消除现状四处手写样板与 wofutil 三重加载（wof_util/detector/executor 各自 LoadLibrary，引用计数无害但重复）；加载器产出的函数表仍是既有工厂注入缝的注入源，接缝零变化。失败语义分级：核心依赖（wofutil、ntdll——压缩/检测/句柄枚举本体）缺失或函数缺失 = 启动即败（现状不变）；可选依赖（rstrtmgr——升级链中段两级）缺失 = 启动探测一次、链构造时直接排除 RM 两级、仅在占用文件走到链尽时于跳过原因中如实报告「RM 不可用已跳过」，成功路径不多话。COM 预备政策：未来若引入 COM，运行时 CoCreateInstance 激活 + 每线程 CoInitialize RAII 配对 CoUninitialize + 缺失降级同分级语义；当前零 COM 使用，不建任何骨架。本 ADR 不取代任何前序决策，作为 0001 工具链约束的机制化延伸；cpp26.md 已增补指向行。
