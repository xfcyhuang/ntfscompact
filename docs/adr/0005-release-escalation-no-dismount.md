# 占用释放逐级升级（无卷卸载）

文件被占用时按升级链逐级释放：⓪ Oplock 前置协商——OVERLAPPED 句柄请求 FSCTL_REQUEST_OPLOCK，短超时（2s）等待授予或锁中断完成，仅对参与 oplock 协议的持有者有效，属被动等待，超时即降级；① Restart Manager 优雅关（RmShutdown(0)）；② Restart Manager 强制关（RmForceShutdown）；③ 句柄强关——NtQuerySystemInformation 枚举系统句柄表，定位目标文件句柄，DuplicateHandle(DUPLICATE_CLOSE_SOURCE) 强关，带风险闸门：默认只关低风险占用者（索引器/杀毒临时句柄/自启辅助进程），explorer.exe、数据库/虚拟机/编辑器类有状态进程与系统关键进程默认跳过，--force-close-all 为显式逃生开关，被关 PID/进程名经输出审计；系统/受保护进程以 PROCESS_DUP_HANDLE 打不开即自然止步；④ 仍占用则跳过报告。不变量：绝不 TerminateProcess、绝不卷卸载。提权语义：Oplock 与 RM 两级对自有进程无需提升，仅句柄枚举与强关他人进程需要管理员权限，非提权走到句柄级自动止步并如实报告。触发与重试结构沿用执行前探测（零共享打开占用才进链）、执行后 SHARING_VIOLATION(32) 再走链自然升级，链内晋级间退避探测（100/300/1000ms，单文件总预算 5s）。卷卸载整链排除、连极端开关一并移除——0004 的实盘教训：系统卷上 FSCTL_DISMOUNT_VOLUME 几乎必败或卸载后立即重挂，独占一步到位的设计在实践中等于没有占用处理。本 ADR 取代 0004（直接卷卸载及其 DismountFn 接缝全部移除），恢复 0003 升级链主体并去除其 --dismount 极端开关；0003 保留为前身记录。
